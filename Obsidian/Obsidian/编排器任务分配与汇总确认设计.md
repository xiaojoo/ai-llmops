# 编排器任务分配与汇总确认（confirm_plan / confirm_result）设计

> 关联代码：`internal/core/agent/agents/orchestrator_agent.py`、`internal/core/agent/entities/queue_entity.py`、`internal/core/agent/agents/agent_queue_manager.py`、`ai-code-llmops-web/src/components/AskUserOptions.vue`
> 前置能力：[[Agent交互式选项选择设计]]（ask_user 事件 / wait_for_choice / 前端确认框，均已实现）

## 背景

ask_user 交互在编排器（OrchestratorAgent）下不生效：主 Agent 的 plan / direct_answer / summarize 节点不经过 `_tools_node`，ask_user 无法触发；子任务虽走 `_tools_node`，但被 `required_tools` 过滤挡掉。需求调整：**子任务执行期间不弹框**，改为主 Agent 在**任务分配后**和**汇总后**提供确认点：

1. **确认点 1（任务分配，必现）**：plan 拆出子任务方案后弹框，用户逐项勾选保留/移除子任务，可填自定义原因；确认后子任务才并行执行。
2. **确认点 2（汇总，LLM 自主）**：summarize 后 LLM 判断汇总结果有无歧义，无歧义直接完成；有歧义弹框"确认完成 / 重新生成"。

## 需求确认

- 确认点 1 交互：**两轮弹框**——用户填自定义原因后，原因作为新要求传给 plan 重拆，融合后重新弹框确认（最多 2 轮）
- 子任务勾选默认态：**全不选**；超时按**推荐选择**（全量子任务执行，任务不卡死）
- 自定义输入语义：作为**新要求传入 plan 重拆**
- 重新规划按钮：**必须填原因**（否则禁用）
- 确认点 2：无模糊直接完成；有模糊弹框"确认完成 / 重新生成"
- 确认点 2 超时：按"确认完成"处理
- 子任务执行期间：不弹框（保持现状）

## 总体流程

```
用户提问
  │
  ▼
plan ──→ 拆出子任务方案（SubTaskSpec 列表）
  │
  ▼
【确认点 1】confirm_plan 节点：发布 ask_user（携带结构化子任务方案）→ 前端弹框
  │            展示：子任务勾选列表（默认全不选）+ 自定义原因输入 + 确认/重新规划
  │            ↑ wait_for_choice 阻塞等待（复用现有 Redis 等待 + event_id 绑定）
  │
  ├─ 确认（勾选保留项）──→ 按 keep_orders 过滤 sub_tasks → execute 并行执行（不弹框）
  │                              │
  │                              ▼
  │                         summarize → 汇总答案
  │                              │
  │                              ▼
  │                        【确认点 2】confirm_result 节点：LLM 判断汇总有无歧义
  │                              │
  │               有歧义 ──→ 发布 ask_user（"确认完成 / 重新生成"）→ 用户选择
  │                              │            ├─ 确认完成 → END
  │                              │            └─ 重新生成 → 回 plan（带用户原因重拆重跑）
  │               无歧义 ──→ 直接 END（不弹框）
  │
  ├─ 重新规划（必须填原因）──→ plan_feedback 传给 plan 重拆 → 融合原因重新弹框（最多 2 轮）
  │
  └─ 超时（300s）──→ 按推荐选择 = 全量子任务执行（不卡死任务）
```

## 协议扩展

### AgentThought 新增字段（queue_entity.py）

- `sub_task_options: list[dict]`：承载子任务方案 `[{order, title, role_prompt, expect_output, required_tools}]`，供前端渲染勾选列表（现有 `options` 是纯字符串，装不下结构化数据）
- 确认点 2 复用现有 `options`（`["确认完成", "重新生成"]`）+ 自定义输入（原因）

### 提交协议扩展（确认点 1）

```json
// 确认执行
{ "task_id": "...", "action": "confirm", "keep_orders": [1, 2, 3], "custom": "", "event_id": "..." }
// 重新规划（必须填原因）
{ "task_id": "...", "action": "replan", "keep_orders": [], "custom": "第二个子任务要改用ABAC方案", "event_id": "..." }
```

- `wait_for_choice` 的 payload 从 `{choice, skip}` 扩展为 `{action, keep_orders, custom, skip}`（向后兼容：旧 payload 无 action 时按 choice 处理）
- 确认点 2 仍用 `{choice, skip}` 格式（choice = "确认完成"/"重新生成"，custom 为原因）

## 后端节点实现

### confirm_plan 节点（新增，plan 之后）

```python
def _confirm_plan_node(self, state: AgentState) -> AgentState:
    """任务分配确认：发布 ask_user 展示子任务方案，等待用户确认/重新规划"""
    specs = state["sub_tasks"]
    if not specs:
        return {"sub_tasks": specs}  # 无子任务（direct_answer 场景）不弹框

    ask_event_id = uuid.uuid4()
    self.agent_queue_manager.publish(state["task_id"], AgentThought(
        id=ask_event_id, task_id=state["task_id"],
        event=QueueEvent.ASK_USER,
        question="请确认任务分配方案：勾选需要执行的子任务",
        options=[s.title for s in specs],
        sub_task_options=[s.model_dump(exclude={"task_id"}) for s in specs],
        allow_custom=True,
        tool=ASK_USER_TOOL_NAME,
        tool_input={"question": "请确认任务分配方案", "options": [s.title for s in specs]},
        message=messages_to_dict(state["messages"]),
        latency=0,
    ))

    action, keep_orders, custom, skipped = AgentQueueManager.wait_for_plan_choice(
        state["task_id"], timeout=ASK_USER_WAIT_TIMEOUT, event_id=str(ask_event_id),
    )
    if skipped:  # 超时：按推荐选择 = 全量子任务
        return {"sub_tasks": specs}
    if action == "replan" or custom:
        return {"plan_feedback": custom, "sub_tasks": []}
    keep = set(keep_orders) if keep_orders else {s.order for s in specs}
    filtered = [s for s in specs if s.order in keep]
    return {"sub_tasks": filtered}
```

### plan 节点改造（融合 plan_feedback）

- `state.get("plan_feedback")` 拼进 prompt；`state["plan_attempts"]` 计数，超过 2 轮不再重拆
- `confirm_plan` 检测到 replan → 返回 `{"plan_attempts": plan_attempts + 1}` 回 plan

### confirm_result 节点（新增，summarize 之后）

```python
def _confirm_result_node(self, state: AgentState) -> AgentState:
    """汇总确认：LLM 判断汇总答案是否有歧义，有则弹框"""
    verdict = self.llm.with_structured_output(ConfirmVerdict).invoke([
        SystemMessage(ORCHESTRATOR_CONFIRM_PROMPT_TEMPLATE),
        HumanMessage(content=state["query"]),
        SystemMessage(content=state["final_answer"]),
    ])
    if not verdict.need_confirm:
        return {}  # 无歧义，直接 END

    ask_event_id = uuid.uuid4()
    self.agent_queue_manager.publish(state["task_id"], AgentThought(
        id=ask_event_id, task_id=state["task_id"],
        event=QueueEvent.ASK_USER,
        question=f"汇总结果存在以下需要确认的点：{verdict.reason}\n请选择：",
        options=["确认完成", "重新生成"],
        allow_custom=True,
        tool=ASK_USER_TOOL_NAME,
        tool_input={"question": verdict.reason, "options": ["确认完成", "重新生成"]},
        message=messages_to_dict(state["messages"]),
        latency=0,
    ))
    choice, skipped = AgentQueueManager.wait_for_choice(
        state["task_id"], timeout=ASK_USER_WAIT_TIMEOUT, event_id=str(ask_event_id),
    )
    # 注意：确认点 2 的自定义输入（原因）在 ask_user 组件里作为 choice 提交（选中"重新生成" + 自定义文本），
    # wait_for_choice 返回的 choice 可能是 "重新生成" 或自定义文本；custom 需从 payload 扩展解析
    if skipped or choice == "确认完成":
        return {}  # 完成（超时也按完成）
    # 重新生成：custom 为用户填的原因（可能为空），回 plan 重拆
    return {"plan_feedback": custom, "sub_tasks": [], "plan_attempts": 0, "regenerate": True}
```

> **custom 来源（明确）**：确认点 2 提交走 `{choice, skip}` 格式；为拿到用户填的原因，`wait_for_choice` 需返回 payload 中的 `custom`（扩展返回 `(choice, skipped, custom)` 或由 submit_choice 把自定义文本合并进 choice）。**设计选定**：前端在确认点 2 选中"重新生成"且填了原因时，提交 `{ choice: "重新生成", custom: "原因" }`；`wait_for_choice` 扩展为返回 `(choice, skipped, custom)`（默认 custom=""，向后兼容）。

### 新增模型与常量（agent_entity.py）

```python
class ConfirmVerdict(BaseModel):
    """汇总歧义判断：LLM 结构化输出"""
    need_confirm: bool = False  # 汇总结果是否需要用户确认
    reason: str = ""            # 需要确认的原因（need_confirm=True 时展示给用户）

ORCHESTRATOR_CONFIRM_PROMPT_TEMPLATE = (
    "你是任务结果审核助手。下面给出了用户的问题和基于子任务执行结果的最终汇总答案。\n"
    "请判断这个汇总答案是否完整、明确、无歧义，是否足以让用户直接采用：\n"
    "1. 答案完整且无歧义，用户可以直接采纳 → need_confirm=false\n"
    "2. 答案存在不确定性、缺少关键信息、涉及多个可选方向需要用户决策 → need_confirm=true，并在 reason 中简述需要用户确认的点\n"
    "只输出 JSON：{{'need_confirm': bool, 'reason': str}}"
)
```

### 图结构（orchestrator_agent.py `_build_agent`）

```python
graph.add_node("plan", self._plan_node)
graph.add_node("confirm_plan", self._confirm_plan_node)
graph.add_node("direct_answer", self._direct_answer_node)
graph.add_node("execute", self._execute_node)
graph.add_node("summarize", self._summarize_node)
graph.add_node("confirm_result", self._confirm_result_node)

graph.set_entry_point("plan")
graph.add_conditional_edges("plan", self._plan_condition)           # 有子任务→confirm_plan / 无→direct_answer
graph.add_edge("confirm_plan", "execute")                          # 确认后执行
graph.add_conditional_edges("confirm_plan", self._replan_condition) # replan→回plan
graph.add_edge("execute", "summarize")
graph.add_edge("summarize", "confirm_result")
graph.add_conditional_edges("confirm_result", self._confirm_done_condition)  # 完成→END / 重生成→回plan
graph.add_edge("direct_answer", END)
```

### 条件边定义（明确）

```python
@classmethod
def _replan_condition(cls, state: AgentState) -> Literal["plan", "execute"]:
    """确认点 1：重新规划（plan_feedback 非空且重拆未超轮）回 plan，否则 execute"""
    if state.get("plan_feedback") and (state.get("plan_attempts") or 0) < 2:
        return "plan"
    return "execute"

@classmethod
def _confirm_done_condition(cls, state: AgentState) -> Literal["plan", "__end__"]:
    """确认点 2：重新生成（regenerate 标记）回 plan，否则结束"""
    return "plan" if state.get("regenerate") else END
```

### 队列层扩展（agent_queue_manager.py）

**新增 `wait_for_plan_choice`**（不改动现有 `wait_for_choice`，避免破坏普通 ask_user / 确认点 2 路径）：

```python
@classmethod
def wait_for_plan_choice(cls, task_id, timeout=300, event_id=None) -> tuple[str, list[int], str, bool]:
    """等待任务分配确认：返回 (action, keep_orders, custom, skipped)

    解析 payload {action, keep_orders, custom, skip}；超时/异常 → ("confirm", [], "", True)。
    action 缺省时按 confirm 处理（旧载荷兼容）。
    """
```

- 现有 `wait_for_choice` **保持不动**：普通 ask_user、确认点 2 仍用它，返回 `(choice, skipped)`
- `submit_choice` 扩展：接受 `action` / `keep_orders` / `custom` 可选参数，写进 payload（缺省时保持旧 `{choice, skip}` 结构，向后兼容）

### confirm_result 的"重新生成"语义（明确）

- "重新生成"（含用户填的原因 custom）→ 回 plan 节点，`plan_feedback=custom`，`plan_attempts=0` 重置
- 重拆后**仍会经过 confirm_plan 再确认一次**（满足"两轮弹框"需求：确认点 1 的 replan 与确认点 2 的重新生成共用同一 confirm_plan 确认环节）
- `regenerate` 标记：用于 confirm_result 条件边区分"重新生成"（回 plan）与"确认完成"（END）；plan 节点看到 regenerate 时把 `state["query"]` 附带"用户要求重新生成"上下文

## 前端 UI

### AskUserOptions.vue 扩展为两种模式

| 模式 | 适用 | 交互 |
|---|---|---|
| `option`（现有） | 普通 ask_user、确认点 2 | 选项按钮 + 自定义输入，点选即提交 |
| `plan`（新增） | 确认点 1（任务分配） | 子任务勾选列表（默认全不选）+ 自定义原因输入 + `确认执行` / `重新规划` 按钮 |

- `plan` 模式 Props：`subTaskOptions: { order, title, role_prompt, expect_output }[]`、`requiresReason: boolean`（重新规划必须填原因）
- 提交 payload：
  - 确认执行：`{ taskId, action: 'confirm', keepOrders: [1,2,3], custom: '', skip: false, eventId }`
  - 重新规划：`{ taskId, action: 'replan', keepOrders: [], custom: '原因', skip: false, eventId }`（custom 必填否则按钮禁用）

### 三个入口接入（PreviewDebugChat / IndexView / HomeView）

- SSE 分支新增：把 `data.sub_task_options` 存入 thought
- 渲染判断：`sub_task_options` 存在 → `mode="plan"`，否则 `mode="option"`
- `onChoiceSubmitted` 调 choice 接口，body 按模式：
  - plan 模式：`{ action, keep_orders, custom, skip, event_id }`
  - option 模式（含确认点 2）：`{ choice, custom, skip, event_id }`（确认点 2 选"重新生成"+填原因时，`choice="重新生成"`、`custom="原因"`）

### 历史回显

确认点 1 的 ask_user 事件落库含 `sub_task_options` + 用户最终 choice（action/keep_orders 序列化），历史消息还原勾选态。

## 测试策略

**后端单元测试**（`test/internal/core/agent/`）：
1. confirm_plan 发布事件：有子任务 → 发布 ASK_USER 含 `sub_task_options`；无子任务 → 不弹框
2. 确认执行：wait_for_plan_choice 返回 `("confirm", [1,3], "")` → sub_tasks 过滤为 order 1,3
3. 重新规划：返回 `("replan", [], "原因")` → state 带 plan_feedback + sub_tasks 清空
4. 超时：skipped=True → 全量子任务
5. plan 融合 feedback：拼进 prompt；超过 2 轮不再重拆
6. confirm_result：need_confirm=False → 直接 END；need_confirm=True → 发布 ask_user；选重新生成 → 回 plan
7. 图结构：confirm_plan/confirm_result 节点存在且边正确

**前端**（vitest）：
1. AskUserOptions plan 模式：渲染勾选列表、默认全不选、确认执行 emit、重新规划无原因禁用
2. 三端 SSE：sub_task_options 存入 thought；模式判断

**联调验证**：
1. 编排应用提问 → 确认点 1 弹框 → 勾选部分子任务 → 确认 → 子任务执行 → 汇总 → 无歧义直接完成
2. 构造歧义场景 → 确认点 2 弹框 → 确认完成 / 重新生成
3. 超时场景（临时调小超时验证）→ 全量子任务执行
