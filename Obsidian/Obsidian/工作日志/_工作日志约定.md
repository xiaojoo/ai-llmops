# 工作日志约定（每次工作必写 Obsidian）

> [!important] 硬性规则
> **每次工作会话都必须把工作内容写入本库**，至少完成两项：
> 1. 在 `工作日志/` 下写一篇当天的日志（见 [[模板]]）；
> 2. 如果工作涉及可复用的结论（架构分析、设计方案、决策、踩坑），单独建一篇项目笔记，并在日志里用 `[[wikilink]]` 关联。

## 为什么

- 会话之间记忆不连续，Obsidian 是**跨会话的持久记忆**；
- 项目笔记沉淀可复用知识，工作日志提供时间线回溯；
- wikilink + 标签让知识可检索、可关联（见 [[Agent记忆系统分层设计]]、[[工作流引擎架构分析]]）。

## 写入流程

1. 会话开始：读一遍 `工作日志/` 最近几篇，回顾上下文（如需要）；
2. 会话过程中：产出结论立即落笔记，不要等到结束；
3. 会话结束：写当日日志，包含：
   - 本次目标 / 完成项
   - 关键结论与决策（附原因）
   - 发现的问题 / 踩坑
   - 遗留待办与下一步
   - 关联笔记（wikilink）

## 文件结构

```
Obsidian/
├── 工作日志/
│   ├── 模板.md            # 日志模板
│   └── YYYY-MM-DD.md      # 当日日志
├── 工作流引擎架构分析.md   # 项目/专题笔记（可放根目录或建专题目录）
└── ...
```

## 命名与格式约定

- 日志文件名：`YYYY-MM-DD.md`
- 项目笔记：用中文描述性名字（如 `工作流引擎架构分析.md`）
- 所有笔记带 frontmatter：`tags`、`date`、`status`
- 用 `[[wikilink]]` 关联库内笔记；外部链接用 `[text](url)`
- 重要提醒用 callout：`> [!warning]` / `> [!danger]` / `> [!tip]`
